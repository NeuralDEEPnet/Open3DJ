# Competitive Landscape: AI / Agentic CAD (as of 27 October 2026)

**Research dimension:** Competitive landscape of AI / agentic CAD for the Open3DJ planning effort.
**Method:** Web search (extended mode) plus direct fetches of vendor docs, GitHub repositories, pricing pages and trade press, all performed 27 Oct 2026. Where a vendor page would not load (Autodesk Fusion blog, PTC Onshape Labs page, Tripo pricing, Zoo plan table) the gap is stated and a secondary source is used. Star counts are from GitHub pages fetched today unless noted.

## Executive summary

By late 2026 "agentic CAD" has split into four camps. (1) **Agent-native code-CAD platforms** led by Zoo (KCL + Zookeeper + an MIT MCP server) whose geometry engine is proprietary and cloud-only. (2) **Incumbents bolting MCP onto existing desktop/cloud CAD**: Autodesk now ships three official Fusion MCP servers (local, data, and a cloud "Compute" beta exposing 7,000+ endpoints), PTC ships an early-access Onshape FeatureScript MCP, while Dassault (SOLIDWORKS "Aura/Leo/Marie") and Siemens (NX copilots) ship assistants but no official agent protocol. (3) **Open-source code-CAD plus MCP**: build123d/CadQuery servers, the 23.5k-star `earthtojake/text-to-cad` skills library, FreeCAD and Blender MCPs, and two young pure-Rust B-rep apps (SolidCraft, 11k stars; vcad, 439 stars). (4) **Generative mesh** (Tripo, Meshy, Rodin, Spline, Womp; open weights TRELLIS.2 and Hunyuan3D 2.1) which is useful for concepts but not engineering. Two kernel events in 2026 reshape the open field: OCCT 8.0 (May 2026, LGPL-2.1 with exception, BRepGraph, C++17) and NVIDIA open-sourcing the SMLib kernel as USD BRep under Apache-2.0 (Oct 2026). Nobody yet combines open source, local-first B-rep, a stable typed agent contract, built-in verification/evidence, sandboxed execution, multi-session concurrency and pluggable cloud GPU providers. That intersection is Open3DJ's opening. The competitors that matter most are Zoo, SolidCraft, the Autodesk Fusion MCP trio, the build123d/text-to-cad ecosystem, and Adam.

## 1. Product-by-product survey

### 1.1 Agent-native code-CAD platforms

**Zoo (formerly KittyCAD): KCL, Design Studio, Zookeeper, Zoo MCP.**
- *What an agent can do:* The `KittyCAD/mcp` server (MIT, v0.28.14 released 26 Oct 2026) exposes `start_modeling_session` / `get_modeling_sessions` / `stop_modeling_session`, `execute_kcl`, `exec_kcl_project` (mock preflight then real execution), `mock_execute_kcl`, `import_cad_file`, `snapshot`, selection/highlight/camera tools, KCL sample search, and `export_kcl` to STEP/STL/OBJ/GLB/FBX. PR #310 (merged 15 Oct 2026) moved KCL execution, exports, measurements and persistent sessions onto "Zoo's CPU engine pool", which is Zoo-hosted, not the user's machine. Limits stated in the README: one modeling session per server process, no credential isolation between owners, binaries not code-signed. Zookeeper is the conversational agent built on Zoo's Agent API (accepts images, documents, 3D models, text); Design Studio 1.2 (28 May 2026) added a geometric constraint solver to sketches and KCL.
- *Kernel:* proprietary GPU B-rep engine built with OpenNURBS and Vulkan; "the 3D view in Design Studio is just a video stream from our hosted geometry engine." The Design Studio app (`kittycad/modeling-app`, MIT, 1.3k stars, Electron + Rust/WASM KCL interpreter) is open; the engine is not.
- *Open vs closed:* app and MCP open (MIT); engine, Text-to-CAD ML and Zookeeper closed.
- *Pricing:* Free / Plus / Pro / Enterprise. Zoo's Zookeeper announcement gives the free tier $10/month of Zookeeper credit and pay-as-you-go at $0.50/min; a third-party review checked 30 Sep 2026 lists Plus $20/mo, Pro $99/mo, Team $399/user (unverified against Zoo's own table, which did not render). Free and Plus allow Zoo to train on user data unless the user opts out. API usage is billed per second; failed calls are free; MCP has no separate fee.
- *Platforms:* native macOS/Windows/Linux app plus web; FAQ: modeling, rendering, Zookeeper and sync "require an internet connection"; no offline mode.
- *Limitations:* single-part focus rather than assembly synthesis, no manufacturability guarantee, no view of PDM/part libraries (per a competitor review, so weight accordingly); sketches inside custom KCL functions cannot be edited with UI tools; STEP export drops the KCL recipe.

**Adam (adam.new) and CADAM.**
- *What an agent can do:* Adam is "an AI CAD copilot for hardware teams" with connectors for Onshape, Autodesk Fusion, SolidWorks and other local apps via a desktop connector, Rhino, and Arena PLM. It publishes a versioned REST API (`/v1`, OpenAPI) and an authenticated MCP server (OAuth with RFC 8414/9728 metadata) for "Adam projects and tasks", plus `llms.txt`. The docs do not say what geometry formats the API returns.
- *CADAM* is the open-source sibling: GPL-3.0, 5.3k stars, OpenSCAD compiled to WASM in the browser, exports STL/SCAD/DXF, LLM backends Claude/OpenAI/Google/OpenRouter.
- *Business:* YC W25; raised $4.1M (TechCrunch, 31 Oct 2025). Plans Free / Pro / Max / Team / Enterprise; prices not retrievable from the page text (TechCrunch quoted $5.99 and $17.99 in 2025; a 2026 directory says paid from $20/mo).
- *Limitations:* closed; mesh/OpenSCAD lineage on the open side; the copilot's value depends on the host CAD's own API.

### 1.2 Incumbent CAD vendors

**Autodesk Fusion.** Autodesk's help centre documents two servers and a blog/beta adds a third:
- *Fusion MCP* (local): "Real-time modeling and command execution in a live Fusion session"; requires the desktop app running, the server enabled under Preferences > General > API, and any MCP client (Claude Desktop, Cursor, any MCP HTTP client); no authentication, local only; tool set is discovered dynamically and "may evolve between releases". Anthropic's connector page lists it as added May 2026 (Adam's explainer says April 2026).
- *Fusion Data MCP* (cloud, OAuth): hubs, projects, folders, items via the Manufacturing Data Model; no Fusion install needed.
- *Fusion Compute MCP* (public beta): cloud-hosted Fusion sessions exposing "more than 7,000 endpoints" of the TypeScript API: sketches/features CRUD, assemblies and joints, CAM setups and posted NC code, STEP/STL export. Beta limits: two concurrent sessions per user, one-hour max session, 15-minute idle kill, queuing, ephemeral sessions; requires an active Fusion licence and a Fusion Team hub. A separate "Fusion Automation MCP" is in limited beta.
- *Roadmap:* AU 2026 (15-17 Sep) previewed AutoTimeline (beta), AutoConstrain, AutoAssemble and System Modeler with rollout in 2027.
- *Kernel/licence:* Autodesk ShapeManager; closed; subscription (personal-use eligibility for the MCP is not stated by Autodesk). A third-party guide quotes Autodesk's own caveat that the MCP is "not yet reliable for complex models or full assemblies."

**Onshape (PTC).** AI Advisor (15 Oct 2025, Amazon Bedrock) answers questions about Onshape itself, not the user's model. Onshape Labs (July 2026) shipped the FeatureScript MCP Server on 13 Aug 2026 (App Store subscription, early access): an LLM generates FeatureScript, inserts it, runs it and refines it, producing a reusable custom feature; it does not read assemblies or edit documents generally. Document read/export goes through the REST API and community servers (hedless/onshape-mcp, altendky, a Rust `onshape-mcp`). Parasolid kernel; cloud-only; Standard about $1,500/user/yr, Professional about $2,500/user/yr (third-party figures).

**SOLIDWORKS / 3DEXPERIENCE (Dassault).** Virtual companions Aura (2025), Leo (engineering, mid-2026) and Marie (materials, later 2026), built on Mistral models on Outscale. R2026x FD03 (Aug 2026) shipped Leo features: assembly performance analysis, thread-to-cosmetic simplification and SpeedPak creation, assembly-instruction generation, writing SOLIDWORKS macros from text, and selection guidance. No official MCP; community SolidWorks MCP servers exist (one AGPL-3.0). Parasolid; closed; Windows desktop plus 3DEXPERIENCE cloud.

**Siemens NX.** Design Copilot NX (mid-2025) is a documentation/best-practice chat with citations; NX CAM Copilot generates machining strategies; Designcenter X NX Copilot (May 2026). No official MCP; community `NX_MCP` (NXOpen automation) and `nxopen-mcp` (offline API knowledge index). Parasolid; closed.

**Shapr3D.** No public API or scripting interface; AI limited to rendering and support chat per community posts (May 2026). The community `shapr3d-mcp` works around this by modelling in build123d and round-tripping STEP into Shapr3D (macOS only; parametric history lost). Parasolid; closed.

**nTop.** Implicit-modelling kernel (nTop 5.0) with the nTop Core developer library embedded in Materialise software; a Synera add-in connects to Synera's agent layer; CEO blog (Apr 2026) says the company is making models "traversable and modifiable by something other than a human" but no MCP or public automation API was found. Closed; Windows desktop.

**Plasticity.** 2026.2 (Oct 2026) adds reusable assets, live constraints, PolySplines. Parasolid plus xNURBS; perpetual licences Indie $175 / Studio $299; Windows 10+, macOS 12+, Ubuntu 22+. No scripting API, AI or MCP.

### 1.3 Copilots, reverse engineering and design automation

**Backflip AI.** CAD copilot GA 4 Aug 2026 as an Autodesk Fusion add-in and web app: 3D scans, meshes, 2D drawings and photos become feature-tree parametric models (extrusions, revolves, patterns) exported as STEP; focus on moderate-complexity 3-axis milled/turned parts. Third-party pricing: Builder $20, Pro $50, Business $380 per month; Fast Mode 10 credits, Thinking Mode 50 credits per job; 3-4 free jobs. Closed; cloud.

**Leo AI (getleo.ai).** Retrieval-grounded engineering copilot: PLM Q&A, 120M+ vendor parts, calculations with citations, assembly reuse; integrations with SOLIDWORKS/PDM, Inventor, Fusion, NX, Teamcenter, SAP PLM; web app; SOC 2; no API/MCP published. Pricing conflicts across directories ($15-$39/user/month; Business about $1,800/user/yr). Leo also publishes most of the comparative "MCP for CAD" articles, so its framing favours a layer above CAD.

**Trinckle (paramate, fixturemate).** Cloud design-automation engine (algorithmic CAD plus configurators), not LLM-driven; Stratasys is embedding its apps in GrabCAD Print (10 apps summer 2026, 15 by Formnext Nov 2026).

### 1.4 Open-source desktop CAD and their MCP servers

**FreeCAD 1.x.** FreeCAD 1.1 released 25 Mar 2026 with 1,700+ changes (toponaming fixes extended, assembly and FEM, materials, theme system); 1.1.4 is the current bugfix release; LGPL-2.0; OCCT-based (exact OCCT version not confirmed in sources fetched). `neka-nat/freecad-mcp` (MIT, 3.1k stars) runs an RPC add-on inside a live FreeCAD GUI and lets MCP clients create/edit models, run arbitrary Python, inspect documents, take screenshots and run CalculiX FEM; FreeCAD must stay open. `blwfish/freecad-mcp` exposes 30+ tools (updated Sep 2026). Older forks are unmaintained since 2025.

**Dune3D.** GPL-3.0, 2.1k stars; OCCT kernel plus the SolveSpace constraint solver used as a library; v1.4.0 "Einstein" (28 Jan 2026) added DXF export and all-bodies STEP export; Linux/Windows/macOS; no CLI, scripting API or MCP.

**Blender.** Blender Lab's official MCP server (v1.0.3, Sep 2026; Blender 5.1+) with 26 tools (code execution, scene summaries, screenshots, renders, doc search; six `_for_cli` variants) and the warning that it "will execute LLM generated code in Blender without any guards in place." Community `ahujasid/mcp-for-blender` (MIT, 32.5k stars, renamed Sep 2026) exposes 9 tools including `execute_blender_code`, `generate_3d` (Hyper3D Rodin) and asset search; its socket has no authentication or encryption; a paid Premium tier covers generation without API keys. Mesh only, no STEP.

**OpenSCAD.** No stable release since 2021.01; the Manifold backend has been non-experimental in nightlies since 2024-09-28 and is the practical path (Debian's 2021.01 CGAL build cannot finish BOSL2 gears in 60 s). MCP servers: `jhacksman/OpenSCAD-MCP-Server` (MIT; compile, preview, export scad/stl/csg/3mf), `fboldo/openscad-mcp-server` (beta), `RobertCoop/openscad-mcp` (MIT; renders, sections, watertightness, printability, interference), `jabberjabberjabber/openscad-mcp`. Meshes only.

**CAD-MCP style projects.** `daobataotie/CAD-MCP` (MIT, 642 stars) drives AutoCAD/GstarCAD/ZWCAD over Windows COM with 35 tools (2D draw/edit/layers/blocks, screenshots, `send_command` passthrough); stdio and Streamable HTTP. Windows-only, 2D.

### 1.5 Code-CAD libraries and agent skill ecosystems

**build123d / CadQuery (OCCT via OCP).** build123d 0.11.1 is current. Servers: `pzfreo/build123d-mcp` (Apache-2.0, 132 stars; persistent session with `execute`, `validate`, `edit_feature`, `find_candidates`, PNG/SVG/DXF renders, measure, printability, `compare`, STEP/STL/DXF/SVG export; HTTP mode has no auth and one shared session; claims CADGenBench June 2026 score 0.360 to 0.457 and validity 88% to 100% for the same model); `Casys-AI/mcp-build123d` (Deno, mass properties, STEP/STL/GLB); `jdilla1277/agentcad` (Apache-2.0; execute with versioned STEP and metrics, render, export, validate, inspect, diff; Claude Code/Cursor/Windsurf). A BuildCAD guide found "no maintained CadQuery server worth listing"; BuildCAD itself sells a hosted build123d MCP (300 runs/day, no desktop CAD).

**`earthtojake/text-to-cad`.** MIT, 23.5k stars, "Give your agent CAD superpowers": 12 skills (CAD, step.parts, engineering drawing PDFs, DXF, URDF/SRDF/SDF, SendCutSend pre-checks, DfAM printability, DFM for sheet metal/CNC/moulding with cited rules, G-code via OrcaSlicer, Bambu Lab printing) backed by the `cadgen` package on build123d/OCP with OCCT 7.9; works with Claude Code, Claude Desktop, Codex, Cursor, Gemini, Grok Build. No app, no UI, telemetry on by default.

**Replicad / JSCAD / OpenCascade.js.** Replicad (MIT, 709 stars) is the browser B-rep layer over a custom OpenCascade.js build (OCJS v1.1.1 stable, beta line in progress); `@taucad/replicad` 0.21.0 (Apr 2026). JSCAD (MIT, 3.3k stars) is CSG/mesh, "stable" but volunteer-maintained and polygon-limited. 3dj.app already builds on Replicad/OCCT 7.7.2 WASM.

### 1.6 New open B-rep entrants (2026)

**SolidCraft (tangency-labs).** MIT OR Apache-2.0, about 11.0k stars, v0.24.0 released 27 Oct 2026 (daily releases). Pure Rust; kernel "SolidCore, a Rust port of SMLib, NVIDIA's open-source C++ geometry library"; own constraint solver. Features: sketches with constraints, extrude/revolve/sweep/loft, fillet/chamfer/shell/draft/holes/threads/patterns, parameters with unit-aware expressions, assemblies with joints, motion, interference, mass properties, sheet metal, plastic features; STEP/IGES/3MF/STL/OBJ/glTF/URDF. Platforms: Windows installer, macOS universal DMG, Linux AppImage/Snap, FreeBSD, browser app, headless CLI, and `solidcraft-cli mcp` (headless or `--connect` to the running app over a token-protected localhost channel). MCP tools: `list_commands`, `describe_command` (JSON Schemas), `execute`, `batch` (ordered, rollback on error), `inspect_design`, `measure`, `body_topology`, `set_parameter`, `screenshot`, `export`, `undo`/`redo`, `open`/`save`/`new_design`, `pending`/`running`, `skill_reference`; path jails; `--param-check strict`. Self-described "Early but usable for simple parts" (75 of 76 reference parts match expected mass properties); installers not code-signed.

**vcad (ecto/vcad).** Apache-2.0 (Municipal Robotics Corp.), 439 stars; custom half-edge B-rep kernel in Rust/WASM (about 35K LOC, 20+ crates): primitives, booleans, fillets, chamfers, shell, 2D constraints, extrude/revolve/sweep/loft, assemblies with joints and forward kinematics, physics "gym" interface; STEP import, STL/GLB/STEP/DXF export; web app, native macOS SwiftUI app, `vcad-cli`, `@vcad/mcp` (`create_cad_document`, `export_cad`, `inspect_cad`, `gym_step`, `gym_reset`).

**Anvilate.** Pre-alpha (v0.0.1); the deterministic engineering-check core exists; the NL front end, 3D geometry and STEP export are roadmap. **ClassCAD / smlibpy (AWV Informatik).** ClassCAD is a headless C++/WASM engine with free MCP tooling (`@classcad/mcp`, 264 documented methods) but a paid engine (free tier: private use only, no STEP export). `smlibpy` 0.6.0 (MIT) is a Python layer on the SMLib kernel with an MCP server, per-session process isolation with crash replay, STEP/USD/DXF/SVG/STL/glTF/.brep export.

### 1.7 Generative 3D (mesh) and creative tools

- **Tripo:** credit billing (frozen on start, refunded on failure); AWS Marketplace overage $0.01/credit; Pro about $20/mo annual.
- **Meshy:** prepaid API credits; text-to-3D preview 5 credits (older models) or 20 (meshy-7.1/6), image-to-3D 20-35, remesh 5, rig 5, printability analysis free; `lowpoly` retires 30 Oct 2026.
- **Rodin (Hyper3D):** Free pay-per-result at $1.50 per direct credit; Creator $30/mo; API only on Business $120/mo ($96 annual).
- **Open weights:** TRELLIS.2-4B (MIT) needs 24 GB VRAM, Linux only, PBR GLB at up to 1536^3; Hunyuan3D 2.1 needs 10 GB (shape) / 29 GB (shape plus texture) and its licence excludes the EU, UK and South Korea and caps at 1M MAU. Open-weights 3.x was not found.
- **Spline V2** (21 Aug 2026): AI chat agent, external MCP access for Claude Code/Cursor, editable scenes, WebGPU; Hobby/Pro/Max. **Womp:** browser text/image-to-3D with integrated printing; "Womp Spark" conversational modelling; no agent API.

### 1.8 Kernels and benchmarks that change the calculus

- **OCCT 8.0.0** (7 May 2026; 8.0.1 on 30 Jul 2026): C++17 minimum, BRepGraph (graph topology with history), STEP files about 20% smaller with thread-safe read/write and PMI, BVH-based intersections, ARM64 first-class on macOS/Windows, VTK off by default; LGPL-2.1 with Open CASCADE exception.
- **NVIDIA USD BRep (SMLib)**: Apache-2.0, first release 8-9 Oct 2026, 1.9k stars; booleans, fillets, sweeps, offsets, shelling, healing, tessellation, NURBS and analytic surfaces, C++ and Python, OpenUSD import/export and OpenCASCADE converters both ways; PyPI wheels for CPython 3.12 on Linux x86_64/aarch64 and Windows; NVIDIA is "currently not accepting contributions"; documented caveats include repairs that can fail silently and mis-oriented triangles.
- **CADGenBench** (Hugging Face `HuggingAI4Engineering`, Apache-2.0): tool-agnostic STEP submissions scored on validity (gate), shape similarity (surface F1, IoU), interface match (keep-in/keep-out volumes) and Betti-number topology; June 2026 digest put the best aggregate at 0.4514 across 11 models; later snapshots disagree (59.6% in Aug, 84.5% in Sep for the generation task). CADBench's best image-conditioned IoU was 0.412. Research agrees that validity, grounding and verification, not fluency, are the bottleneck (AgenticCADedit, Zero-to-CAD, ReliCAD, Embodied CAD, CADEngBench).

## 2. What they all miss

1. **Open + local-first + true B-rep + agent-native, in one product.** Zoo has the best agent contract but a cloud-only closed engine. Fusion/Onshape are closed and licence-gated with concurrency caps (Compute MCP: 2 sessions, 1 hour). FreeCAD/Blender MCPs need the GUI open and run arbitrary Python. build123d/text-to-cad are local and open but are libraries, not an application: no persistent model, no UI, Python-environment friction. SolidCraft is the closest, but weeks old in its current form, "usable for simple parts", on an unproven ported kernel.
2. **A stable, typed, versioned contract for agents.** Only SolidCraft publishes JSON Schemas per command; only agentcad and build123d-mcp offer diffs/compare. Nobody combines schema'd tools, transactional batches with rollback, persistent named references that survive edits (3dj.app's `withReferences`/`attachTo` is the only example), semantic design diffs, and deterministic replay.
3. **Verification as a first-class output.** Agents mostly "look at their own screenshot". No open product ships an evidence pack: validity/watertight gate, wall-thickness and overhang checks, interference, mass properties with units, dimension confidence, STEP provenance. CADGenBench's validity gate and the 88% to 100% jump from build123d-mcp's checks show how much this matters.
4. **Security model.** Blender Lab's server runs LLM code "without any guards"; mcp-for-blender's socket has no auth and four 2026 CVEs; build123d-mcp HTTP has no auth; freecad-mcp executes Python. No one offers sandboxed (WASM/process-isolated), capability-scoped execution with path jails and token-protected local transport by default (SolidCraft's bridge is the partial exception).
5. **Concurrency and branching.** One session per process (Zoo MCP), one shared session (build123d-mcp HTTP), two cloud sessions (Fusion Compute). No branch/merge of a design document by multiple agents.
6. **Assemblies, joints and tolerance stacks for agents.** Zoo is single-part; Autodesk says its MCP is not reliable for assemblies; code-CAD servers stop at compounds. SolidCraft and vcad have joints but little verification around them.
7. **Hybrid compute.** Nothing runs geometry locally while bursting generative-3D, FEA or rendering to interchangeable cloud providers; generative APIs are vendor-locked credit systems and open weights need 24 GB-plus NVIDIA GPUs.
8. **Portable design history.** STEP drops the recipe everywhere; KCL is open but tied to a closed engine. An open, text, git-diffable design document that round-trips to STEP AP242, 3MF, glTF and USD BRep does not exist.
9. **Open reverse engineering.** Scan/drawing-to-CAD is closed (Backflip at $20-$380/month).
10. **Standard content and DFM.** Only `text-to-cad`'s skills and 3dj.app's `lib.*` offer fasteners, pockets and DFM rules; neither is inside a local modelling app.
11. **Human review UX for agent work.** Plan/diff/approve flows, person-only confirmations (Anvilate's elicitation PR) and evidence views are absent from every shipping CAD UI.
12. **Benchmark-driven engineering.** No product ships CADGenBench-style self-evaluation in CI or exposes scores.

## 3. The competitors to beat

1. **Zoo (KCL + Zookeeper + Zoo MCP).** The reference agent-native stack: readable parametric language, constraint solver, agent API with images/3D input, MIT app and MCP, release cadence measured in days. Beat it on local/offline execution, open kernel, no metering, multi-session, and verification.
2. **SolidCraft.** Same thesis as Open3DJ (open, local, desktop plus web plus CLI plus MCP, pure Rust, permissive licence), 11k stars and daily releases. Beat it on kernel maturity (OCCT 8 vs a fresh SMLib port), agent contract depth (references, diffs, evidence), security sandboxing, cloud-GPU plugins and manufacturing workflow; or partner.
3. **Autodesk Fusion MCP trio.** Distribution to millions of seats, 7,000+ endpoints, CAM, assemblies, Claude connector in-box. Beat it on openness, cost, concurrency, reproducibility, and being runnable headless on any machine.
4. **build123d / `text-to-cad` ecosystem (plus agentcad, pzfreo/build123d-mcp).** 23.5k stars of agent skills on OCCT, DFM/DfAM checks, drawings, slicing, service integrations. Beat it by being an application with persistent models, UI, references and sandboxing while remaining compatible (import/execute build123d and CadQuery scripts, expose the same skills).
5. **Adam.** Venture-backed copilot across Onshape/Fusion/SolidWorks/Rhino with REST and MCP; owns the "copilot inside your existing CAD" narrative. Beat it with an open engine agents can own end-to-end rather than drive through host-app APIs.

Watch list: Blender MCP (32.5k stars, mesh/visualisation bridge worth integrating rather than fighting), Backflip (scan-to-CAD), Onshape FeatureScript MCP (if PTC widens scope), ClassCAD/smlibpy (AWV is productising SMLib agent tooling fast).

## 4. Recommendations for Open3DJ

- **Kernel:** build on OCCT 8.0.x (LGPL-2.1 with exception; dynamic linking keeps MIT app code clean) for proven B-rep, fillets, STEP AP203/AP214/AP242 and 20-plus years of healing; keep the kernel behind an internal trait so NVIDIA USD BRep (Apache-2.0, converters to/from OCCT already exist) can be a second backend or exchange path. Do not write a kernel first; vcad and SolidCraft show the cost. Ship a WASM build (OCJS/Replicad prove feasibility) for browser and sandboxed execution.
- **Agent contract:** typed command catalogue with JSON Schema per command (`list_commands`/`describe_command`), transactional `batch` with rollback, persistent named references (3dj.app's `withReferences`/`attachTo`/`onFace` semantics), semantic diff and deterministic replay, long-running job model with `pending`/`running`. Expose it identically over MCP (stdio and Streamable HTTP with token auth), CLI, and an OpenAPI HTTP server; publish `SKILL.md` packs for Claude Code, Codex, Cursor and Gemini like `text-to-cad`.
- **Verification built in:** every result returns an evidence block (validity, watertight, bounds, mass properties, wall thickness, overhang, interference, dimension confidence, provenance hash) plus multi-view renders and pixel diffs; run CADGenBench in CI and publish scores; treat validity as a gate.
- **Security by default:** scripts run in a WASM or process sandbox with path jails, no arbitrary host Python unless explicitly enabled, token-protected localhost bridge, signed installers (Zoo and SolidCraft both ship unsigned binaries today).
- **Concurrency and history:** per-agent sessions, branchable text design documents (git-friendly, like KCL but open), merge and review tooling, undo/redo exposed to agents.
- **Local-first, cloud-pluggable:** CPU/GPU local by default; a provider plugin interface for generative 3D (Tripo, Meshy, Rodin, 3dj.app fleet, self-hosted TRELLIS.2/Hunyuan3D with their VRAM and licence caveats: TRELLIS.2 is MIT but 24 GB/Linux; Hunyuan3D 2.1 excludes EU/UK/KR), FEA (CalculiX as FreeCAD does), rendering and print quoting (3dj.app as one provider).
- **Own the gaps competitors leave:** assemblies with joints, mates and tolerance stacks for agents; standard content library (ISO fasteners, pockets, snap fits, T-slot) and DFM/DfAM gates in-core; an open scan/drawing-to-CAD pipeline; a human review UI (plan, diff, evidence, approve) with person-only confirmations.
- **Interop:** STEP AP242 with PMI (OCCT 8 adds it), 3MF, glTF/GLB, DXF, URDF, USD BRep; import build123d/CadQuery/OpenSCAD scripts; Blender bridge; FreeCAD and Fusion via STEP.
- **Licensing hygiene:** keep GPL components (CADAM, OpenSCAD, Dune3D, Blender add-on code) out of the core process; respect LGPL dynamic-linking for OCCT; avoid Hunyuan3D in bundled distributions for EU users.
- **Platforms:** Windows/macOS/Linux desktop (Tauri or Electron shell around the Rust/C++ core), headless server, browser build; ARM64 is first-class in OCCT 8.
